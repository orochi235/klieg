# The run model — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `fire()` takes a list of styled runs, so one word can mix fonts, sizes and tints, with all
layout coming from `@weasel-js/text`.

**Architecture:** Read [the design](../specs/2026-08-30-run-model-design.md) first — it carries the
decisions and the traps. In short: klieg deletes its own `layoutLine`/`layoutBlock` and lays out
through `layoutRuns`; it keeps `wrapBlock`, whose fit-maximising search now scores candidates by
measuring them through weasel; it uses weasel for **positions only** and keeps its own
opentype→`THREE.Shape` glyph pipeline; and a run's size goes on a scale node inside the letter cell,
because the pose owns `cell.scale`.

**Tech stack:** TypeScript, three.js, opentype.js, `@weasel-js/text@1.3.0-pre.0`, vitest.

```ts
}

  srcIndex: number; srcEnd: number; cp: number;

  advance: number;             // the cell's right edge is x + advance
  level: number;               // bidi embedding level; 0 with no resolver
  drawsInk: boolean;           // property of code point + face, stable across calls
}

// @weasel-js/font
function registerFontOutlines(family: string, variant: OutlineVariant, source: OutlineSource,
                              opts?: { parser?: OutlineParser }): void;
function outlineStatus(family: string, variant?: OutlineVariant): 'idle'|'loading'|'ready'|'failed';
function subscribeGlyphReady(cb: () => void): () => void;
function glyphGeneration(): number;

interface OutlineFace {          // every number in EM units; glyphD has already divided by upem
  unitsPerEm: number;
  ascender: number;              // line top to baseline, from hhea
  glyphD(cp: number): string | null;
  advanceOf(cp: number): number | null;   // null only when the face lacks the glyph
  kernOf(left: number, right: number): number;
}
type OutlineParser = (bytes: ArrayBuffer) => OutlineFace | Promise<OutlineFace>;
```

**Three contracts that will silently produce garbage if broken:**

- **A cell's right edge is `x + advance`.** Never `cells[i + 1].x`. Cells are in logical order;
  their x values are not once a bidi resolver reorders a line.
- **`drawsInk` is not "has geometry".** A blank-but-servable glyph (NBSP in a face that has one)
  reports `true`. For exact ink extents, read the geometry.
- **`registerFontOutlines` is synchronous, but the face is not ready when it returns.** Nothing is
  fetched or parsed until a glyph is asked for. Await readiness before the first layout.

```ts
import type { OutlineFace } from '@weasel-js/font';
import type { LoadedFont } from './font.js';

/**
 * weasel asks for metrics in em units and by code point; klieg holds them in font units and by
 * character. Nothing here parses — the face is already open.
 */
export function faceOf(loaded: LoadedFont): OutlineFace {
  const upem = loaded.unitsPerEm;
  const charOf = (cp: number) => String.fromCodePoint(cp);
  return {
    unitsPerEm: upem,
    ascender: (loaded.font.ascender ?? upem * 0.8) / upem,
    // klieg tessellates from its own pipeline, so nothing reads this; it satisfies the contract.
    glyphD: (cp) => {
      const path = loaded.font.charToGlyph(charOf(cp)).getPath(0, 0, 1);
      return path.commands.length ? path.toPathData() : null;
    },
    advanceOf: (cp) => loaded.metrics.advanceOf(charOf(cp)) / upem,
    kernOf: (left, right) => loaded.metrics.kernOf(charOf(left), charOf(right)) / upem,
  };
}
```

If `path.toPathData` is not on the opentype typings klieg has, cast at that call rather than
widening the import — nothing in klieg reads the result.

```ts
import { outlineStatus, registerFontOutlines, subscribeGlyphReady } from '@weasel-js/font';

/** weasel's registry is module-global, so the instance number is what keeps two apart. */
export function familyFor(instance: number, font: string): string {
  return `klieg-${instance}-${font}`;
}

/**
 * Registration returns before the face is usable: nothing is parsed until a glyph is asked for, and
 * a layout run before that silently lays out nothing. So register, then wait.
 */
export async function registerFace(
  instance: number,
  font: string,
  loaded: LoadedFont,
): Promise<string> {
  const family = familyFor(instance, font);
  if (outlineStatus(family) === 'ready') return family;
  registerFontOutlines(family, {}, loaded.bytes, { parser: () => faceOf(loaded) });
  await ready(family);
  return family;
}

function ready(family: string): Promise<void> {
  if (outlineStatus(family) === 'ready') return Promise.resolve();
  return new Promise((resolve, reject) => {
    const stop = subscribeGlyphReady(() => {
      const status = outlineStatus(family);
      if (status === 'ready') {
        stop();
        resolve();
      } else if (status === 'failed') {
        stop();
        reject(new Error(`klieg: ${family} failed to register with the layout engine`));
      }
    });
  });
}
```

- [ ] **Step 5: Verify readiness actually resolves against the real package**

and run it once:

```bash

import { registerFontOutlines, outlineStatus, subscribeGlyphReady } from '@weasel-js/font';
const face = { unitsPerEm: 1000, ascender: 0.8, glyphD: () => null, advanceOf: () => 0.6, kernOf: () => 0 };
```

**Run: this probe falsified the plan's reading of readiness.**

`outlineStatus` reports `'idle'` after registration and never advances on its own, so `ready()` as
written above deadlocks. The suggested fallback deadlocks too: `layoutRuns` does *not* force the
load — it finds no face, lays out nothing, and leaves the status `'idle'` however many times it is
called. Prime the wait with `glyphOutline(family, 400, 'normal', cp)` instead, which flips it to
`'loading'`; `subscribeGlyphReady` then fires on `'ready'` as the plan expects. Note the signature:
`outlineStatus` and `glyphOutline` take `(family, weight, style, …)`, not a variant object.

**One copy of `@weasel-js/font`, or none of this works.** The registry is a module-global `Map`, so
two physical copies are two registries — klieg registers into one, `layoutRuns` reads the other,
every run is silently skipped, and the symptom is zero lines and zero bounds with no warning. npm
hoists `font@1.0.3` here (`@weasel-js/ui` pins it for the dev labs) and nests the `1.3.0-pre.0`
copies separately, which is exactly that failure. The root `package.json` carries an
`overrides` entry forcing `font` to `1.3.0-pre.0` tree-wide; the lockfile must be regenerated for
it to take, and `find . -name package.json -path '*@weasel-js/font/*'` must report one copy.

```ts
import type { StyledRun } from '@weasel-js/text';

/** One span of a fired word that carries its own styling. */
export interface TextRun {
  text: string;
  /** A name from the instance's `fonts`. Defaults to the fire's own `font`. */
  font?: string;
  /** Multiple of the word's size. 1 is the surrounding size. */
  size?: number;
  /** Overrides the fire's `tint` for this span. */
  tint?: number;
}

/** Glyphs are laid out at 1 em, so a run's `size` is its font size outright. */
const EM = 1;

export function styledRunsOf(text: string | TextRun[], defaultFont: string): StyledRun[] {
  const runs = typeof text === 'string' ? [{ text }] : text;
  return runs
    .filter((run) => run.text.length > 0)
    .map((run) => ({
      text: run.text,
      fontFamily: run.font ?? defaultFont,
      fontSize: (run.size ?? 1) * EM,
    }));
}

/** Per-run tint never reaches weasel — klieg paints, weasel only places. */
export function tintOf(text: string | TextRun[]): (slot: number) => number | undefined {
  if (typeof text === 'string') return () => undefined;
  const perSlot: (number | undefined)[] = [];
  for (const run of text) {
    for (const _ of Array.from(run.text)) perSlot.push(run.tint);
  }
  return (slot) => perSlot[slot];
}
```

```ts
import { layoutRuns, type LayoutRunsOpts, type StyledRun } from '@weasel-js/text';

/** One code point of a fired word, in klieg's slot order. */
export interface Slot {
  char: string;
  /** Pen x at this slot's origin, in em. */
  x: number;
  /** This slot's own width. Its right edge is `x + advance` — never the next slot's `x`. */
  advance: number;
  line: number;
  drawsInk: boolean;
}

export interface LaidOut {
  slots: Slot[];
  lines: { baselineY: number; x0: number; x1: number }[];
  width: number;
  height: number;
}

export function layoutRunsForKlieg(runs: StyledRun[], opts: LayoutRunsOpts): LaidOut {
  const laid = layoutRuns(resolveRuns(runs, resolveTextStyle()), opts);
  const slots: Slot[] = [];
  laid.lines.forEach((line, index) => {
    for (const cell of line.cells) {
      slots.push({
        char: String.fromCodePoint(cell.cp),
        x: cell.x,
        advance: cell.advance,
        line: index,
        drawsInk: cell.drawsInk,
      });
    }
  });
  return {
    slots,
    lines: laid.lines.map((l) => ({ baselineY: l.baselineY, x0: l.x0, x1: l.x1 })),
    width: laid.bounds.width,
    height: laid.bounds.height,
  };
}
```

Import `resolveRuns` and `resolveTextStyle` from `@weasel-js/text` alongside `layoutRuns`.

```ts
export function wrapRuns(runs: StyledRun[], budget: Budget, opts: LayoutRunsOpts): LaidOut {
  let best: LaidOut | null = null;
  let bestScale = -1;
  for (const maxWidth of candidateWidths(runs, budget)) {
    // layoutRuns, not cachedLayoutRuns: the cache caps variants per runs array at 8 and evicts the
    // whole set at once, so a search probing more widths than that thrashes its own cache.
    const laid = layoutRunsForKlieg(runs, { ...opts, maxWidth });
    const scale = fitScale(laid.width, laid.height, budget);
    if (scale > bestScale) {
      bestScale = scale;
      best = laid;
    }
  }
  return best as LaidOut;
}
```

`candidateWidths` is the existing enumeration lifted out of today's `wrapBlock` unchanged.

## Deliberately not in this plan

- **Bidi.** `layoutRuns` takes a `BidiResolver` and `@weasel-js/bidi` implements it, so klieg can
  turn real right-to-left on later by installing that package and passing a resolver. The cell
  contract in Task 5 — right edge from `advance`, never from the next cell — is what keeps that a
  switch rather than a rewrite. Reordering still would not make Arabic correct; that needs GSUB
  joining forms this walk does not apply.
- **Per-run `look`.** Bloom is a whole-frame pass.
- **The trailing-space alignment mismatch.** weasel aligns on advance width including a trailing
  space where klieg ranges on ink, so a centred line ending in a space sits half a space off. It is
  a known weasel bug awaiting an upstream fix — do not compensate for it here, and do not chase it
  as a klieg regression in Task 9.
